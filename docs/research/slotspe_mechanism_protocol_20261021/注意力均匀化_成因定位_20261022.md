# 原版 SlotSPE 注意力均匀退化的成因定位

路线：SlotSPE / SPE-08 / mechanism_followup_20261022
性质：**源码事实 + 冻结 checkpoint 诊断**，不是新实验设计，不含预测损害判定

## 0. 为什么需要这项追查

observe 阶段记录到每个槽对全部 256 个 token 均匀分配：token 分配熵 5.545175，
而 log(256) = 5.545177；归一化分配熵 1.000000。当时按协议登记为 P2
"机制证据支持表示/读取冗余"。

该结论本身可信，因为 observe 对原生逐轮重放做了强制校验
（`allclose(atol=1e-6, rtol=1e-5)`，不匹配即终止）。本次进一步独立复核：
用记录的 `initial`/`encoded` 与 checkpoint 权重重建第 0 轮注意力，
与录制值的最大绝对误差为 **1.4e-09**。trace 忠实。

但"槽冗余"这一表述可能指错了层次。追查结果：**槽不是先变得冗余，
而是注意力在第 0 轮就已经均匀，因而所有槽读入相同内容。**
退化发生在注意力之前的输入表示阶段。

## 1. 退化发生在第 0 轮，早于任何迭代动力学

| 量 | 初槽 | 第 0 轮注意力行 |
|---|---|---|
| 平均非对角余弦 | **0.474**（明确不同） | **0.99996** |

初槽本身是相互独立的（`slots_logsigma` 完好，sigma ≈ 1.0045），
但注意力行在第 0 轮就已几乎相同。10 次迭代中余弦从 0.99995 单调升到 0.999998，
token 分配熵始终为 log(256)。这排除了"迭代把槽拉到一起"的解释。

## 2. 塌缩不在 query 投影

| 阶段 | 平均余弦 |
|---|---|
| 原始初槽 | 0.4757 |
| LayerNorm 后 | 0.4761 |
| `to_q` 后 | 0.4670 |

`to_q` 保留区分度，且 bias 范数仅为权重范数的 6%。
查询方向是分明的，塌缩不在这里。

## 3. 真正的塌缩点在输入表示（模型内产生，非数据自带）

同一患者、同一批 patch：

| 阶段 | 平均余弦 | 中心化有效秩 | 首主成分方差占比 |
|---|---|---|---|
| 缓存原始特征 1536-d | 0.2747 | 97.19 / 1536 | 0.123 |
| `Linear₁` 后（ReLU 前） | 0.6857 | 60.55 / 1536 | 0.209 |
| ReLU 后 | 0.6932 | 54.52 / 1536 | 0.243 |
| **`wsi_mlp` 输出 256-d** | **0.9629** | **6.14 / 256** | **0.601** |
| 槽模块 `norm_input` 后 | 0.9629 | 7.20 / 256 | 0.655 |

**数据本身并不共线（余弦 0.275、有效秩 97）。塌缩完全由模型内部产生。**

### 3.1 共同方向逐步占据表示

沿"所有 patch 共享的平均方向"对齐度：

| 阶段 | 与共同方向平均余弦 | 该方向平方占比 |
|---|---|---|
| 输入 | +0.5268 | 0.278 |
| `w1`+ReLU 后 | +0.8333 | 0.694 |
| `w2` 后 | **+0.9813** | **0.963** |

**96.3% 的表示能量落在一个跨全部 patch 共享的方向上。**

### 3.2 逐 token 中心化无法移除它

对 256-d 输出做逐 token 去均值后，共同方向余弦从 +0.9813 变为 **+0.9814**，几乎不变。
原因是该方向对每个 token 都相同，属于 token 间的常数分量，
而 LayerNorm 减去的是**每个 token 内部**的均值，不减 token 之间的均值。
因此 `norm_input` 结构上无法消除它。

### 3.3 ReLU 不是主因（修正早期假设）

用同一组训练权重做反事实：

| 变体 | 平均余弦 | 有效秩 |
|---|---|---|
| 原版 Linear→ReLU→Linear | 0.9629 | 6.14 |
| 去掉 ReLU：Linear→Linear | 0.7355 | 8.67 |
| ReLU 后置：Linear→Linear→ReLU | 0.7714 | 9.73 |

ReLU 有贡献（0.736 → 0.963），但去掉 ReLU 后余弦仍有 0.74、
有效秩仍只有 8.7。**主要塌缩来自 `Linear₂` 这一步 1536→256 的降维本身**，
ReLU 是放大因素而非唯一成因。

注意：`w1` 条件数 50827 属于训练后权重的正常稀疏化现象，
不是首要异常——xavier 初始化同样有 4206，kaiming 有 8170，
训练后更大但同一量级。`w2` 条件数仅 5.11，良态。

## 4. 塌缩如何产生均匀注意力

key 继承输入的共线性（每头平均余弦 0.968~0.985），
而 query 仍然分明，因此 logits 幅度极小：

| softmax 缩放 | logits sd | 槽轴熵（均匀 2.0794） | token 轴熵（均匀 5.5452） |
|---|---|---|---|
| 不缩放 | 3.013 | 5.48566 | 5.45894 |
| 原版 `dim**-0.5` = 0.0625 | 0.188 | 5.54501 | 5.54484 |
| `dim_head**-0.5` = 0.125 | 0.377 | 5.54450 | 5.54383 |
| 4.0（原版 64 倍） | 12.05 | 4.57094 | 4.40956 |

### 4.1 一处独立的源码单位不一致

```python
self.scale = dim ** -0.5        # dim = 256  ->  0.0625
...
dots = einsum('... i d, ... j d -> ... i j', q, k) * self.scale
```

点积在 `split_heads` 之后的 `dim_head = 64` 维上计算，
匹配缩放应为 `64 ** -0.5 = 0.125`。模块按 `dim` 而非 `dim_head` 取缩放，
使 logits 被额外缩小一半。

这是**源码事实**，可独立复核。但需注意两点限制：

1. 它只是把本已接近均匀的 softmax 进一步压向均匀，
   不是均匀化的**根因**。即使修正到 0.125，token 轴熵仍为 5.54383
   （均匀 5.54518），距均匀仅 0.00135 nats。
2. 原版 `heads=8, dim_head=64, dim=256` 时 `dim == heads*dim_head`，
   二者本应一致。当前 checkpoint 确实满足此关系，
   但 `self.scale` 仍按 256 计算而点积在 64 维上，属于实现与约定的错配。

**修正该缩放不等于修复槽注意力**：共线输入仍然存在。

## 5. 对既有结论的影响

| 结论 | 状态 |
|---|---|
| observe 的重放保真 | 不变，误差 1.4e-09 |
| P2 数值事实（余弦 0.998、熵 1.0、有效秩 2.54） | 不变 |
| P2 判定"机制证据支持冗余" | **需改写因果层次**：冗余是下游症状，不是上游成因 |
| P4 同输入读取稳定性 | 不变，但"稳定"是稳定在退化状态上 |
| P7 梯度几何 | 不变；主/辅生存梯度同向的结论仍成立 |
| P3 冷启动 | 不受影响（各臂都在同一退化输入上比较） |

关键修正：**observe 报告把"槽冗余"读作表示层现象，
实际是输入投影塌缩导致的读取均匀化。**
这不影响 P2 支持"存在读取冗余"的判定，但改变了归因方向，
也改变了对 P1（固定容量）的解释：K16 的有效秩 2.95 主要反映输入有效秩 7.2，
而不是槽容量不足。

## 6. 这不是什么

- **不是**迭代动力学导致的塌缩（第 0 轮即已均匀）
- **不是** `slots_logsigma` 塌缩（sigma ≈ 1.0045，完好）
- **不是** `to_q` 或 bias 主导（保留区分度，bias 占权重 6%）
- **不是**数据本身共线（缓存特征余弦 0.275、有效秩 97）
- **不是** trace 失真（重建误差 1.4e-09）
- **未**证明这造成预测损害，也**未**证明任何修复会改善预测性能
- **未**改动原版源码、forward 或 checkpoint

## 7. 后续可检验项（均需另行授权）

1. 在同一 checkpoint 上，仅替换 `self.scale` 为 `dim_head**-0.5`，
   测量均匀化是否缓解。注意这属于对原版 forward 的干预，
   需单独登记为诊断干预，不是原版机制证据。
2. 在 `wsi_mlp` 输出后、槽注意力前，测量跨 patch 共同方向占比，
   作为"输入可分性"的独立指标，纳入后续问题的公共基线。
3. P1 的解释需修正：应区分"槽容量不足"与"输入有效秩不足"。
   二者在本 checkpoint 上无法分离，需匹配训练或输入消融。
