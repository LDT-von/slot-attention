# 原版 SlotSPE 癌区与槽读取分析工具

这套本机工具完成了合成输入的开发与检查，可将**已经捕获**的病理和通路注意力同切片癌区对齐，生成病例图和汇总。图中的输入顺序、切片、坐标与标注必须由使用者先独立核实；目前没有验收真实 BLCA 标注 CSV、服务器特征、真实 checkpoint 或患者结果。工具不能仅凭患者号推断同一张切片，也不会把未标注区域当作正常组织。

本文命令在仓库根目录执行。患者标识、特征、权重、trace、图片及逐病例结果都必须放在被忽略的 `local_evidence/`，不要加入 Git。以下生成式示例不含患者信息；所有输出目录均要求是此前不存在的新目录，工具拒绝覆盖。

## 快速检查和合成示例

依赖包括 Python、NumPy、PyTorch、Matplotlib、Shapely；从真实 WSI 读图还需 Pillow、`openslide-python` 与系统可用的 OpenSlide 库。实际版本与部署应由使用者按环境核对。无需修改原版 `third_party/SlotSPE/`。

```powershell
python -B scripts/analyze_slotspe_annotated_roi.py --plan
python -B scripts/analyze_slotspe_annotated_roi.py --synthetic-demo --output local_evidence/roi_demo_new
```

`--plan` 只打印计划，不读取病例文件、不执行模型。`--synthetic-demo` 构造虚拟特征、虚拟切片、假标注及随机初始化的原版模型，做两次一致性前向并输出图，**不加载真实权重、患者数据或训练模型**；图上有 `SYNTHETIC DATA - NO PATIENT` 标记。重复运行时请换一个不存在的输出目录。

示例目录包含 `capture/case.json`、`capture/trace.npz` 和 `analysis/case_summary.json` 及图片。示例图仅用于检查程序能否运行，不能用于患者结论。

## 真病例接入边界与数据格式

目前没有自动读取病人的原始 WSI、坐标文件、RNA、临床资料、特征和 checkpoint 并完成配对的端到端入口，也没有可直接套用的 BLCA CSV 转换器。接入前需要对每个待分析患者核实：

1. RNA、生存资料、验证集划分和 checkpoint 来源；原版对应的输入通路顺序。
2. 输入特征的每一行对应哪张**确切切片**、切片内的哪一个原始 feature row 及该 patch 在 level-0 的坐标；原版袋含多张切片时，每行单独记录来源。
3. 标注文件对应切片的准确 ID、坐标单位与缩放，独立核对轮廓与切片位置。只有在理解来源格式之后，才能将标注转换为本工具支持的几何格式。
4. 保持原协议的输入与采样，不按癌区过滤输入。原版完整验证袋和 4096 诊断袋必须分别标明；后者原 loader 对不足预算的袋以零补齐，不应将 padding 当作实际 patch。

调用方传入 `save_captured_case` 的 `case` 是 JSON 兼容字典，主要字段如下（示意结构中的名称和哈希占位符必须替换为经过核实的真实值；这不是可直接用于患者的现成配置）：

```text
schema: "slotspe_roi_case_v1"
patches: 按模型实际输入 token 顺序排列的数组，每个条目为
  {token_index: 0, is_real: true, slide_id: "确切切片ID",
   feature_row: 0, box: [level0左, level0上, level0宽, level0高]}
  padding 条目：is_real=false，slide_id、feature_row、box 均为 null。
  未标注切片上的真实行可使用 box=null，但仍需可核对的 slide_id 与 feature_row。
slides: 以切片ID为键的对象，每张切片包含 feature_count、mapping_verified=true、
  mapping_sha256；被标注切片还必须有 coordinate_space="level0"、width、height。
polygons: 以确切切片ID为键的对象，每项包含 coordinate_space="level0"、
  geometries=[GeoJSON Polygon 或 MultiPolygon geometry, ...]。
  Polygon 的环必须闭合，允许孔洞；坐标和 patch 盒必须在切片边界内。
pathway_names: 与组学通路 token 一一对应、顺序一致且不重复的名称数组。
display_slide_id、thumbnail_slide_id: 有缩略图时填写同一个确切切片ID。
provenance: 包含下表字段。
```

| `provenance` 字段 | 含义 |
|---|---|
| `input_protocol` | `original_full_validation` 不允许 padding；`fixed_4096_diagnostic` 要求恰好 4096 个输入 token；`synthetic_fixture` 只用于假数据。 |
| `split_role` | 当前工具要求 `validation`。 |
| `checkpoint_sha256`, `source_sha256`, `signature_sha256`, `split_sha256` | 分别声明权重、原版 `models/SlotSPE.py`、通路签名与划分文件的 64 位小写 SHA-256。 |
| `study`, `feature_encoder`, `checkpoint_selection` | 非空字符串，说明队列、特征编码器、权重选择口径。 |
| `fold`, `training_seed`, `evaluation_seed` | 非负整数。 |

`mapping_verified=true` 与 SHA-256 是调用方声明；程序会检查其格式和内部一致性，但不会自行打开原始提取记录、验证坐标来源或证实上述声明为真。图像展示也必须遵守准确切片 ID；不同切片的 patch 不能叠到当前缩略图上。

## 捕获、保存与事后分析

先由调用方加载已冻结、处于 `eval()` 模式的**原版**模型、明确的输入 batch 和完全按输入顺序排列的 `patches`，并完成真实身份及坐标复核。真实患者使用 `capture_verified` 会执行一次无追踪与一次追踪前向，须先取得明确执行授权；该函数不加载 checkpoint，不做训练。可参照 `slotspe_proof/roi_demo.py` 的完整合成调用；真实输入的构建和权重加载仍需单独完成。

```python
from slotspe_proof.roi_trace import capture_verified
from slotspe_proof.roi_workflow import save_captured_case

# model, batch, case 由调用方先正确构建；此处不提供真实患者路径。
capture = capture_verified(
    model, batch,
    row_manifest=case["patches"],
    pathway_names=case["pathway_names"],
    source_root="third_party/SlotSPE",
)
files = save_captured_case(
    capture, case, "local_evidence/new_case/capture",
    thumbnail=thumbnail,       # 无切片图时可省略
    patch_tiles=patch_tiles,   # 可省略；或传 {输入行号: 图像} 稀疏映射
)
```

捕获检查完整模型输出、槽和解码器输出、逐迭代重放、RNG 及模型状态；同时记录 WSI、组学输入与行清单哈希。真实病例需要传入 `source_root` 通过原版模型纯度检查。`save_captured_case` 只保存捕获结果，不再执行前向；它检查病例行清单和通路顺序与 capture 一致，并在 `case.json` 中写入 trace 哈希及核查记录。这些核查不能代替对切片身份、特征来源和患者配对的独立验收。

已有绑定好的私有 `case.json` 和 `trace.npz` 后，可运行：

```powershell
python -B scripts/analyze_slotspe_annotated_roi.py --run `
  --case local_evidence/new_case/capture/case.json `
  --trace local_evidence/new_case/capture/trace.npz `
  --output local_evidence/new_case/analysis
```

`--run` 只读取保存好的病例和 trace 并计算作图，**不做模型前向、不加载权重、不训练**。病例和 trace 路径必须位于 `local_evidence`，输出目录必须为新目录。运行前核对待分析文件与实际授权范围。`trace.npz` 关闭 pickle 加载；文件和行清单的绑定哈希不一致时会拒绝处理。

### 可选切片图片读取

`slotspe_proof.roi_wsi_assets.extract_slide_assets(reader, *, slide_id, slide_metadata, patches, requested_rows, thumbnail_max_size=1024, tile_size=(224, 224))` 接收调用方准备好的切片 reader；`open_slide_assets(path, **kwargs)` 延迟加载 OpenSlide。返回缩略图 `thumbnail`、按输入行索引的稀疏 `tiles` 和无法从该切片取得的 `missing_rows`。切片几何与边界有检查，无法匹配切片的行不会伪造图片；真实切片文件是否确为声明的 slide ID 仍由调用方核实。本轮仅用合成 fake reader 检查，未打开真实 WSI。可将取得的缩略图与稀疏 tiles 传给 `save_captured_case`。

## 图与统计如何解释

工具输出原切片缩略图和人工癌区轮廓、共用色标的各槽热图、槽间读取重叠矩阵、每槽高权重 patch 图集，以及“槽 × 通路”热图。没有传入缩略图或某些 patch 图片时，相应图片标记缺失，而非补造真实图像。patch 图集默认每槽取前 20 个有效输入；不足 20 时不补足，并报告边界并列信息。注意力保留逐头结果，也给出先平均头、再对真实 patch 条件化的结果，并报告 padding 质量。

面积相交比例以 `0.5` 为主要阈值，另计算 `0.25` 和 `0.75` 灵敏度。阈值以下及未标注切片均为未知，而非正常。少于 20 个癌区阳性 patch 时，癌区专属指标标记为不可充分评估；其他可用的全袋指标仍可查看。

`case_summary.json` 中 `selected_slot_indices_zero_based` 分别给出 WSI 和组学原版选择掩码对应的从 0 开始槽号，`selected_wsi_overlap` 是这些被选 WSI 槽的两两重叠子矩阵；图中的槽号从 1 开始，全槽与各注意力头的指标仍在摘要中。被选槽不等于只参与模型的槽，通路读取也不等于某个基因被读取。应同时看具体相同 patch 的重复、重叠矩阵以及对均匀读取的偏离；多个槽均有癌区权重并不足以证明读取冗余。bulk RNA 无法为某张 patch 提供基因表达真值，表达量亦不能直接当作致癌突变证据。

## 多患者汇总

`--run-cohort` 读取私有 manifest，按每个病例的 `case_summary.json` 文件 SHA-256 检查后汇总，不执行模型。manifest 必须放在 `local_evidence`，结构如下；实际值由调用方填写：

```json
{
  "schema": "slotspe_roi_cohort_manifest_v1",
  "records": [
    {"case_key": "私有患者键", "summary_path": "相对manifest的病例summary路径", "sha256": "对应文件的64位小写SHA256"}
  ]
}
```

```powershell
python -B scripts/analyze_slotspe_annotated_roi.py --run-cohort `
  --cohort-manifest local_evidence/cohort/manifest.json `
  --output local_evidence/cohort/analysis_new
```

默认期望每名患者固定输入下的 20 个初始化种子 `2026102700` 至 `2026102719`，检查同一患者重复记录的特征、行映射、标注及 RNG，并检查队列共同的来源配置；缺失种子的患者标为不完整，不进入完整患者统计。先在患者内汇总，再以患者为单位计算分布及 bootstrap，20 次重复不是 20 名患者。不同 checkpoint、折、协议等不应混为同一组。患者级结果只能描述观察，单病例不能证明普遍性，也不能单独证明生存预测受到损害。
