# 标注癌区与通路的原版槽冗余实验方案

日期：2026-10-27。状态：**方案设计；患者匹配、导出程序和实际实验均未完成**。

## 1. 研究问题和最小结论

在原版 SlotSPE 的冻结权重下，同一患者的多个 WSI 槽是否重复读取**同一批**经人工标注的肿瘤 patch？OMIC 槽是否重复读取同一批通路 token？

实验提供可定位到组织内容的槽读取证据。它不单独证明肿瘤 patch 都具有相同生物学作用、槽中完全没有独有信息、模型产生预测损害或任何修正方法有效。先固定实验方案，再查看患者结果；不能只挑选重叠最明显的病例作总体结论。

## 2. 数据、患者和预先登记

优先沿用 TCGA-BLCA，补充 [Manual tumor annotations in TCGA 的 BLCA.zip](https://zenodo.org/records/5320076)。标注针对诊断 WSI 中的侵袭性肿瘤富集区域，作者不保证像素级精确或完整。包内实际文件结构、坐标单位、切片覆盖及数据许可需在下载后核对，尚未核验。

每名纳入患者必须满足以下条件，并在任何槽结果计算之前建立交集：

1. 属于所用模型和 fold 的验证集；记录该验证集是否还参与 checkpoint 选择。如果用于最佳 epoch 选择，它不属于独立测试集。
2. 同患者有原实验实际使用的 RNA 表达、通路列表、生存及删失信息；固定原有预处理和通路顺序。
3. 模型输入中至少一张诊断 WSI 与标注**按完整切片 ID 或 UUID 严格匹配**。同患者但不同切片不视为坐标可对齐。
4. 每个输入特征行能确认其所属切片及顺序；对标注切片，每个特征行还需通过已有提取记录映射到原 WSI 的坐标和 patch 实际视野，包括原图坐标层级、倍率/MPP、尺寸和步长。其他输入切片若无坐标，仍保留在原版模型和全输入分析中，区域状态记为未知。相同数量或相似文件名本身不构成顺序证明；标注切片无映射、无法核验尺度或缺失特征的病例列为不合格，不能猜坐标。
5. 病例至少有 20 个满足下述癌区判定的真实 patch，才纳入癌区内容分析；较少者单独报告不可评估原因。若实际覆盖不足，将本阈值变更作为协议修订，不能事后静默放宽。

主分析纳入满足条件的**全部验证患者**；同时报告每一道交集的患者数、切片数及排除原因。目标先确认至少 20 名患者是否可用；不足时如实按实际数量作探索分析，20 并非统计功效保证。不要仅选一位最像预期的患者。

图示病例选择不使用模型槽结果：对合格患者 ID 用固定的 `SHA256("slotspe-roi-20261027:" + case_id)` 升序排序，取前 3 名，第一名主图，后两名补充图；实际 ID 和可逆映射保留在私有目录。如遇图像确实不可用，记录原因并顺延。每患者若有多个合格标注切片，以标注的肿瘤 ROI 总面积最大者为主展示切片；所有输入切片仍保留在模型输入和整体指标中。

**标注规则：** 在已确认的原图坐标和真实视野下，patch 与人工肿瘤 ROI 的面积交并比采用 `肿瘤 ROI 与 patch 相交面积 / patch 面积`；比例 ≥ 0.50 定义为“已标注癌区 patch”。其他真实 patch 一律记为“未知/未满足阈值”，不能当作正常或非肿瘤。主分析先固定 0.50，0.25 和 0.75 为敏感性分析。报告满足阈值的 patch 数、患者总真实 patch 数、标注切片占比、区域边界不确定性；空白、缺失和补零单列。

## 3. 模型、权重和输入协议

只使用 `third_party/SlotSPE/` 中的原版网络，`eval` 模式、冻结权重、不更新参数；不加入新的模块、辅助损失或癌区筛选，也不重训练。固定病理槽 8、组学槽 8、10 次迭代和 checkpoint 实际架构配置；若权重实际参数不同，以其真实配置为准并报告，不能硬套。

优先使用来源与训练记录齐全的原版 checkpoint，记下源码、特征提取器、权重、配置、split、训练 seed、epoch、最佳验证或固定末轮、RNA 签名、权重哈希。若是 3 轮/256 patch 历史权重，明确标记为历史探索权重，不能称为 30 轮/4096 结果；不得将诊断队列训练的权重冒称论文发布的原始权重。

**主协议 A：原版验证输入。** `third_party/SlotSPE/dataset/dataset_survival.py` 的采样和补零仅发生在 `split_key == 'train'`；验证集原版读取患者全部实际可用切片的所有 patch，不因图示仅有一张标注切片而截断其他切片。原版验证 loader 的 batch size 为 1。使用该完整输入得到主结果并记录每一行的来源。若显存或文件不足导致不可执行，记录失败及原因，不静默改为子集。

**辅助协议 B：现有诊断队列复现。** 现有 `slotspe_proof/patient.py` 的验证实现采用固定 `sample_seed=0`、4096 预算子集，短 bag 补零；这是诊断队列的协议，不是原版验证 loader 的行为。仅在能复现对应队列运行条件和权重时单独报告 B，不与 A 混合。记录每个抽样行的原始索引与补零行；模型前向保留原样、不加 mask。分析时单列补零所占注意力，不能把补零称为癌区或真实 patch。

原版 Slot Attention 在 `eval` 时仍随机初始化。固定 checkpoint、完整输入、设备与数据顺序，对每位患者预先指定 20 个初始化随机种子 `2026102700` 至 `2026102719`，作为同一患者内部重复而非 20 位患者。主图固定使用第一个种子；所有统计先在患者内部汇总再跨患者统计。记录 RNG 状态和实际执行环境。每次运行的槽编号不保证对应相同语义，患者内两槽重叠不依赖槽编号；跨重复若要逐槽比较，先在同一输入空间作一对一最优匹配，并报告匹配歧义，不把强重叠时的任意匹配当作稳定身份。

## 4. 可观测量和导出验收

原始 `MultiHeadSlotAttention.forward` 返回槽向量，不直接返回注意力；`slotspe_proof/problem_trace.py` 的 `NativeSlotTrace` 有读取各头、各迭代注意力的机制，`tests/test_slotspe_problem_trace.py` 对合成输入检查了 replay 和 RNG 不变。现成组件**尚未形成带标注、坐标和图像的完整端到端导出程序**。

实现时需在原源码之外添加观测与作图代码。每次导出记录：模型与 checkpoint 哈希、设备、模式、输入行顺序、逐头逐槽逐 token 的最后一次迭代注意力、各迭代状态、两侧选中槽、预测 logits、采样与补零映射、RNA 通路名称顺序及本次 RNG。原模型前向开关观测各做一次，用相同输入与 RNG 验证 logits、槽结果与后续 RNG 一致；同设备要求逐元素相等，若不能完全一致则停下并记录误差和原因，不能声称原样复现。同步核对权重前后哈希相同。完整 raw 文件和患者 ID 放在忽略的 `local_evidence/` 下。

现有 `_sample_bag` 返回所选行索引，但 `patient.py` 的 `_batch` 当前调用时丢弃该索引；不能直接假定旧输出已包含行到坐标映射。历史注意力数组只有在单独核实其样本行映射、输入配置和 checkpoint 之后才能复用；否则需要新导出。

## 5. 病理侧预设指标和图

记最后一次迭代中每头的每槽 token 归一化注意力为 `a[h,s,i]`。先保留完整的原生值；主图使用对头取均值后的值，并在每个真实 patch 集上重新归一化为 `p[s,i]`。对协议 B 同时报告补零获得的原生总质量；真实 patch 条件化结果是**分析派生量**，不改变模型前向。图中所有槽使用同一色标，并标注是否按全部真实 patch 条件化；同时报告逐头结果，避免头平均掩盖分工。

预设以下量，所有配对、所有患者和所有重复都报告分布：

1. **全真实 patch 读取重叠**：对 28 对槽，`O(s,t) = sum_i min(p[s,i], p[t,i])`，范围 0–1，越接近 1 表示读取分布越相似。完全均匀的两个槽也会得到 1，所以它首先说明“相同读取”，不能独立说明“都专门关注癌区”。
2. **对均匀读取的偏离**：每槽 `D(s) = 0.5 * sum_i |p[s,i] - 1/N|`，其中 N 为真实 patch 数；0 表示均匀。报告完整分布，并将 `D < 0.05` 标为本方案的“接近均匀操作性标记”，不是公认生物学阈值；对 0.01、0.10 做敏感性分析。
3. **已标注癌区质量及富集**：`M(s) = sum_(i in T) p[s,i]`，`Q = |T| / N`，其中 T 为已标注癌区 patch；`E(s) = M(s)/Q`。报告 M、Q、`M-Q` 和 E，而不是仅报告比例；同时计算两槽在癌区的未条件化共同质量 `O_T(s,t) = sum_(i in T) min(p[s,i],p[t,i])`，其均匀参照为 Q。均匀读取时 E=1；未标注不等于正常，因此这只表示相对全真实输入的**已标注区域富集**，不能叫肿瘤/正常分类性能。
4. **癌区内的同 patch 重叠**：只在已标注癌区内，将每槽权重除以其癌区质量后，再用第 1 项的重叠公式。与第 3 项一起报告：如果多个槽对癌区几乎无权重，癌区内条件化看似相同并不足以说明它们关注癌区。总量、条件化及区域覆盖一并呈现。
5. **Top patch 作为展示**：每槽按真实 patch 权重排序，取 `min(20, N)`；报告两槽 top 集合交集及 Jaccard，另报告 top 集合实际注意力质量以及均匀时的 `K/N`。完全并列按原输入行序确定，同时标记并列及第 K 位附近的权重差。权重近乎均匀或 top 区别只在数值精度范围时，排序仅作展示，不将细微排名差作为稳定“偏好”。

产图：A 原 WSI 缩略图叠加人工 ROI 与展示切片覆盖范围；B 同一尺度 8 张槽热图，显示真实 patch 坐标，未采样/无特征区域为空白；C 每槽同数 top patch 缩略图及同一 patch 在各槽的重复标识；D 8×8 读取重叠矩阵；E 患者层面的重叠、均匀偏离和癌区质量分布，标注患者数。图中的原始切片、逐患者热图及可逆 ID 保存在私有目录；公开图必须先做授权与去标识核查。

## 6. 判读规则与统计单位

预先约定：当同一患者至少 15/28 对槽的全真实 patch 重叠 `O ≥ 0.90` 时，记为“高读取重叠”的操作性描述，不视为生物学阈值。若同时至少 5/8 个槽 `D < 0.05`、其 E 在 0.8–1.2 之间，应解释为**共同近均匀读取、缺少明显癌区富集**。若读取重叠高、至少 5/8 个槽同时满足癌区 E ≥ 1.5 和 M ≥ 0.10、且至少 15/28 对槽的癌区内条件重叠 ≥ 0.90，可描述为**多个槽重复读取相同标注癌区内容**；同时报告 D 和 O_T，避免小面积 ROI 的比例富集掩盖绝对质量很小。上述门槛均为事先约定的示例性操作规则，未达到不等于不存在冗余。这仍是读取层证据。判断对每次初始化分别计算，再按第 6 节的患者单位汇总并报告重复间波动。

“明显富集”预先采用 E ≥ 1.5 作展示用操作性界线，并同步提供连续 E、M 和 Q；它不是经过临床验证的阈值。将 O 的 0.80/0.95、D 的 0.01/0.10、E 的 1.2/2.0 作为敏感性分析，不以事后挑出的阈值替换主结果。若各槽偏好不同 patch、不同区域或者重叠不高，应明确记录**未观察到该患者的该项重复读取**；若有效标注少或位置映射缺失，则记录“不可评估”，不是阴性。

患者是主要统计单位。每患者先对 28 对槽和 20 个初始化重复计算预先固定的中位数，再对患者汇总中位数、四分位数、满足操作性阈值的比例及分母。若条件允许，用患者为重采样单位、固定种子 `20261027`、2000 次 bootstrap 计算探索性 95% 区间；不得把 patch、槽对或重复初始化当成独立患者。样本不足或无法计算时只报告描述统计，不假称显著或具备普遍性。

## 7. 基因侧：先通路、后单基因

原版 `Pathways` 模式先按实际 signature 把基因组编码成通路 token，再交给 OMIC Slot Attention。因此先输出每患者 8 槽×实际通路的末轮注意力热图，槽对读取重叠、相对均匀偏离、top 通路和全部基因集名称；固定预先登记的基因集版本和顺序。根据现有 signature 实际名称检查是否有 p53、RTK/FGFR、细胞周期、免疫等相关集合，找不到就如实记缺失，不临时换库或挑结果好看的通路。

组学槽对同一通路的注意力相近，支持**通路 token 的重复读取**，并不直接证明单个基因被重复读取。不同通路包含相同基因会导致重复计数。单基因结果列为第二阶段：先明确固定槽标量、参考输入、归因方法、随机初态重放和重叠基因汇总规则，再在合成输入验证及数据许可完成后实施；归因是模型响应分析，不是突变或因果证据。FGFR3、TP53、RB1 等是候选癌症相关基因，但患者是否存在突变需独立突变数据确认。bulk RNA 不赋予某张图像 patch 的空间基因真值。

## 8. 实际执行顺序和停止条件

1. 只读检查可用路径、checkpoint 元数据、切片/特征/坐标映射以及公开 BLCA 标注格式；记录数据版本与哈希。无法对齐则停在此步。
2. 编写独立的观测、对齐、汇总与绘图工具；只用合成数据验证坐标变换、标签未知态、补零隔离、顺序映射、并列和公式，验证原版前向和 RNG 保持一致。
3. 用户明确授权后，先对一个预先选定患者执行冻结前向和图形检查；如前向验证、数据映射、图像方向、单位或权重哈希失败，停止，不输出肿瘤位置结论。
4. 在用户授权范围内，对全部合格验证患者运行，输出患者级汇总和预定三例图片，并保留“不支持/不可评估”的病例；不启动训练。

本设计阶段未下载 BLCA.zip、未读取患者数组或模型权重、未运行服务器、未做模型前向、未统计患者交集。患者数据和运行权限以实际环境及用户明确授权为准。
