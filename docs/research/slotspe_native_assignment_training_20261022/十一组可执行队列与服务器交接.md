# 十一组可执行队列与服务器交接

## 1. 路线与范围

原版 SlotSPE 的槽冗余对照，统一顺序为 **S0、S4、R1、R2、R3、R4、R5、S1、S2、S3、S5**。仅使用服务器已有的 **BLCA、UNI2-h 预提取特征、fold0、seed3**。不增加队列、fold、seed，不重新提取特征。

默认每臂 **3 epochs、256 real patches、逻辑 batch 8、20 次评估重放**，使用最终 epoch，不按验证集挑最好 checkpoint。这是单折短程诊断，不能表述为充分训练、泛化改善或临床收益。

## 2. 已完成内容与方法约定

统一入口已接入原生 256 维、8 槽、10 次槽迭代的训练流程。原版源码、原有默认队列和 A/B/C 定义保持原状；适配位于独立模块。

| 方法 | 两侧内容或表示的改动 |
|---|---|
| S0 | 原版；R0 仅为其别名，不额外训练 |
| S1 | 双侧普通 Sinkhorn |
| S2 / S3 | 分别仅病理 / 组学使用 `mesh_uniform` |
| S4 | 双侧 `mesh_uniform` |
| S5 | 双侧 DIAS 第 3.2 节去冗余再聚合核心；不是整套 DIAS 复现 |
| R1 | 原版分配，加 Gram 去相关，权重 10 |
| R2 | 原版分配，加 Slot-BERT 式损失移植，权重 1、温度 0.5 |
| R3 | R2 加 query-free 内容集合重构，重构权重 5 |
| R4 | 仅加 query-free 内容集合重构，权重 5 |
| R5 | Gram 权重 10，加内容重构权重 5 |

这些系数是固定诊断预设，未证明对患者最优，不在验证集调参。S6 当前预设存在过度压缩风险，本队列暂缓。

内容目标使用真实输入维度：训练折拟合固定均值和标准差，WSI 与各异构基因通路分别固定投影至 32 维，再为单例生成至多 8 个内容中心；评估不拟合或更新参考，不读取生存结局。S5 的变长槽采用矩形 Hungarian 加未匹配项覆盖损失，避免少槽自动获得低重构误差。这与此前 8×16 的生成数据模板不同，内容目标仍只是特征重构参照，不代表已识别生物学事件。

## 3. 路径与提交

新入口：`scripts/run_slotspe_redundancy.py`；固定候选定义：`configs/slotspe_redundancy_queue.json`。核心实现为 `redundancy_queue.py`、`redundancy_engine.py`、`redundancy_content.py`，位于 `survot_rank/research/slotspe_proof/`。

本轮具体提交 SHA 由交付消息提供。服务器应核对该 SHA 已包含于 `origin/main`，不要沿用历史报告中的旧提交。

## 4. 验收与执行记录

本地生成数据相关验收 **152 项通过**；完整 **14 阶段、11 臂**执行烟雾测试通过，完成后 resume 没有重新训练。完整烟雾测试采用原生 **256 维、8 槽、10 迭代**，输入为 **7 个虚构样例、1 epoch、8 patches、2 次评估**，计数为 **121 次宿主前向、297 次槽注意力调用、33 次核心优化、33 次探针优化**。

这些是实现与执行链验证。本机患者任务 **0**、实际服务器执行 **0**；尚无这 11 臂的真实 BLCA 结果或服务器原始收据。

## 5. 输出与缺口

输出必须进入新的、被忽略的 `local_evidence/redundancy_blca_uni2h_fold0_seed3_run01/`。默认目录若已有部分执行或失败残留，保留它并换新的 run 编号，不覆盖、不删除。

需要验收根目录 `summary.json`、`summary.txt`、队列阶段与哈希记录，以及各臂的训练曲线、最终 checkpoint、重复评估、诊断与预测文件。报告两侧 cos / 绝对 cos / RMS、槽范数、有效配对覆盖率与单槽比例、内容 own / donor / static 误差、主辅及新增损失梯度尺度、重复 C-index、耗时和资源记录。单槽 pair cosine 记为未定义，不能填 0；cos 下降也不能单独判定方法有效。

逐患者特征、标识、权重、预测和原始数组只保存在 `local_evidence/`，可通过既有私下回传渠道验收，禁止加入 Git。最终仍缺真实单折短程结果，更不具备跨折或临床结论。
