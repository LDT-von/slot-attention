# 共有、私有与跨模态交互：研究方案草案

**最新入口：**先读 [严格架构审查](ARCHITECTURE.md) 和 [AI交接清单](HANDOFF.md)。本页下方保留第一版方案；新修订以两份文件为准。`model.py` 是旧骨架，不是新架构的入口。`components/` 是本轮准备的零件，尚未组装和运行；`checks/run_static.py` 只运行标准库契约与数学检查，`deferred_checks/` 的张量检查尚未执行。不要运行本页旧的 tensor 测试并将其混入本轮结果。

状态：2026-11-03 已完成无数据副作用的模型组装接口和元数据适配器契约；不是已验证的新方法，也不是患者训练入口。本目录汇集后续模型、消融与验收设计。原版 SlotSPE 与既有队列不变。

`components/assembly.py` 提供 `CommonPrivateSynergyModel`、`ObjectiveWeights` 和 `build_model`。它接收已经完成身份编码的两模态 token 与显式 real mask；同一模态的两个视图复用同一个 encoder、pool 和 projector。任务预测读未投影 summary，DeCUR 式项和方差项按权重独立启用，关闭项不检查输入。该文件只定义接口，尚未进行模型初始化、前向/反向或训练。

`components/adapters.py` 只定义未来接入所需的 `FeatureTokenSchema`、`PatientPairContract`、`TimeBinContract` 和 `AdapterContract`。它不会读取数据；组学必须声明 gene/pathway 身份编码，配对和时间分箱必须提供训练折来源与哈希。真实特征类型、患者对齐和 tensor adapter 仍未实现。

## 目标与候选贡献

学习与预后相关的共有信息，保留有用的模态私有与跨模态协同信息，减少无效重复，再利用所有槽预测生存。候选研究问题是：能否在控制表征容量和训练条件后减少无效重复，同时保留对生存预测有增量的信息？分支名称、低相关性与整体分数均不能单独回答它。

DeCUR、PIBD、Deep Sets 和 Φ-Omni 已分别研究相关分解、集合读出或协同问题；把这些组件组合不自动构成新颖性。创新主张需由具体机制、近邻对照和严格结果共同支持，当前只称候选路线。

## 结构草图：先分角色，再用全部槽

1. 同一患者的病理特征集合和组学特征分别构造两个视图，每模态使用共享参数的编码器。
2. 每个模态以**可学习、角色指定的槽查询从编码开始分组**：7 个共有候选槽、1 个私有候选槽，合计仍是每模态 8 槽。两视图应使用同一组参数和角色；不能在编码结束后仅改标签就称提前划分。7:1 是用户提出的首选假设，另做 6:2、4:4、8:0 等容量匹配对照；一个私有槽可能是瓶颈。对齐单个槽的位置需要额外假设，优先比较组级或置换不敏感的读出。
3. 两模态共有候选经可学习聚合和跨模态融合为 G，G 是向量而不是额外注意力槽。每个模态的私有候选保留在读出中。应让 14 个共有候选槽的信息有明确的全槽汇总路径，而不只读其中一部分。
4. 对各槽先做非线性映射再组内汇总，结合 G、两侧私有摘要及**跨模态交互候选分支**输出离散时间生存风险。交互分支提供表达能力，不能因此称为 PID 协同。共享分支可选独立生存头作为消融：生存监督使其有任务压力，但不能保证纯共有或无协同泄漏；联合、单模态和共有头都使用同一删失约定与训练折拟合的时间分箱。
5. 基础编码与额外监督分开开关，anti-collapse、SRO、SCM、R4 为后续可归因对照，不作为一次性堆叠的结论。原生信息有界残差只作为保留信息的控制，不能证明分支语义。

## 两视图与增强：不能假装已有原图增强

- 若拥有真实病理 patch 图像及对应编码器，可先在图像域做经过病理学检查的裁剪、翻转或适度染色扰动，再分别提取特征；须保持患者和 patch 对应关系并记录编码器、增强随机种子与视图生成方案。真实预后信号可能对颜色或形态敏感，增强并不天然保标签。
- 如果只有预提取 UNI2-h 向量，无法还原图像增强。可比较两种明确不同的特征视图：同患者 real patch 子集重采样（允许部分重叠，必须分析组织覆盖和稀有区域丢失）及温和特征扰动（只作为代理，先验证幅度和稳定性）。不得把重采样说成对每个 patch 做了两次图像增强。短袋零填充不参与增强统计；原版对照仍保留原始 loader 行为，掩码或处理改变应独立对照。
- 基因可以构造视图，但不是随意修改突变或表达值：先核实输入究竟是表达、突变还是既有通路特征。对于连续表达/通路特征，候选是轻量遮蔽或有界噪声；比例、尺度与标准化仅由训练折确定，记录缺失标记，拒绝整模态或全通路消失。真实稀有强信号可能被遮蔽，必须做不增强、不同强度及信号保留对照；离散突变不可按连续表达加噪冒充生物学变化。两视图仍配对同一患者，不把增强视图当独立患者。
- 只在训练时做随机增强；验证和测试规则提前固定。组学基于训练折拟合的变换不得使用验证/测试患者统计。若使用两个部分重叠的病理子集，二者所含形态不同，强一致约束可能抹掉稀有内容，需分别检测。

## 目标函数：有控制的 DeCUR 式适配

令 W、O 两模态各有两个增强视图。候选的三项是：W 模态内跨视图冗余约简、O 模态内跨视图冗余约简、跨模态共有对齐与私有交叉相关抑制。前两项作用于各自共有与私有表示，鼓励同模态两个视图保留稳定信息；第三项把共有部分跨模态相关矩阵推近单位阵，把私有部分跨模态线性相关推向零。仅为 DeCUR 思想的槽级适配，不是原论文的逐项复现；损失权重和各项归一化先记录再比较。

私有的跨模态相关接近零不能排除非线性复制、跨分支泄漏或噪声；同模态一致性也不保证保留预后信息。患者 batch 太小会使相关矩阵估计噪声大；不能将一个患者的多个槽冒充独立样本。需先做合成已知答案测试和对有效患者批量的敏感性分析。梯度累积不自动等价于合并相关统计。

DeCUR 原文切分的是投影**维度**而非槽，87.5% 共有比例是其 SAR-optical 条件下的结果，其他设置使用不同的比例；本方案的 7:1 是结构假设而不是论文证明的最佳槽数。三类损失包括两个模态内项和跨模态共有、私有两个部分，不能都称作模态内损失。

当前代码在组级摘要上计算四项相关损失，并分别对相关矩阵的对角和非对角元素取均值；原 DeCUR 的表达式按元素求和，二者权重尺度不同。批量 2 虽可计算但估计极不可靠；近零方差直接报错，不能把接口通过视为适于真实小样本训练。

候选总目标为生存 NLL + 两个同模态项 + 跨模态项，权重由训练折内的预设方案决定；共有独立生存项和反塌缩各有独立开关。旧条件 KL 无法单独防复制，不作为已经成立的去重机制，也不与 DeCUR 损失不加对照地同时堆叠。跨模态任务增量/协同的可训练目标仍待确定，不把交互层自动叫作协同损失。

## 协同的验证与限制

Φ-Omni 针对 WSI、基因和报告的预训练表征，以融合表示为信息目标，并非直接证明本方案中病理与组学对删失生存结局的 PID。这里需要明确目标为生存结局，以及删失下可估计量、PID 定义和估计器适用范围。

原文以联合互信息减各单模态互信息的差值为目标的一部分，并使用高斯近似。两源标准 PID 下该差值对应协同减冗余，不能直接视为协同本身；三源分解还有更丰富的部分冗余项。我们不直接复用其差值并宣称得到精确生存 PID。

先在已知答案合成数据上分别设置共享、单模态独有、XOR 协同、无关噪声、复制和非线性混杂；冻结编码器、匹配头容量和训练预算，对比全模型、两单模态、加性头和非线性交互头。XOR 的成功只说明该任务中可读交互，不证明真实患者 PID。患者阶段采用预定指标比较联合与适当单模态/加性模型的独立测试表现，并使用有条件替换或配对破坏控制；简单删槽、打乱模态可能产生分布外样本，其结果只能是敏感性证据。预后数据应按患者配对与重采样，不能把各槽或重复视图当独立病例。

## 分阶段消融和验收

| 阶段 | 对照问题 | 控制要求 |
| --- | --- | --- |
| P0 | 现有原版 SlotSPE、既有共有/私有原型、新结构无额外损失 | 实现和训练协议不同须明示，避免裸分数归因；匹配数据/分割/预算 |
| P1 | 角色 7:1 与 6:2、4:4、8:0；无角色全槽控制 | 保持总槽数、维度与读出能力尽量匹配；8:0 不定义私有损失 |
| P2 | 无增强、双视图及三项 SSL 分项 | 分离增强和损失；只在有效多患者 batch 计算相关 |
| P3 | 有/无共有独立生存头；加性/交互读出 | 控制参数量和训练预算，检验任务增量而非只看相关 |
| P4 | anti-collapse 单独开/关 | 几何指标与生存预测并报，避免把低余弦等同有效 |
| P5 | 新方法基线再分别加入 SRO、SCM、R4，最后才考虑组合 | 逐项定义可兼容接口，单臂一变量；禁止把原 SlotSPE 专用实现直接称已迁移 |

历史 SCM 是对超阈值槽对余弦的惩罚；SRO 是对槽读取真实 token 的重叠惩罚；R4 使用无目标 query 的内容集合重构，其共享 MLP 接受逐槽输入，不读目标 token、槽 ID 或位置，并不是跨视图统计量重构。它们原本依附于旧结构、注意力和内容目标；迁移需要明确新接口。私有组仅 1 槽时不存在组内槽对，不能以零损失宣称去冗余成功。SCM/SRO 在完全对称塌缩点可能梯度为零，反塌缩干预须做单独已知答案验收。

比较前锁定训练折拟合、随机种子、患者配对、数据与算力预算、删失约定、选权方式和评估。原版验证集最佳 epoch 不等于独立测试；重复评估不是独立训练。先用生成数据测试形状、掩码、梯度、视图对应、退化输入、噪声和已知答案，再考虑申请具体患者执行。不同阶段结果分别记录，保留失败与不确定性。

## 交付和未决问题

本目录 `model.py` 是模型接口骨架：复用现有研究 `SlotEncoder`，以各查询索引划分角色，对槽做非线性汇总，提供跨模态交互、风险 logits 和分项 DeCUR 式相关损失。它不实现增强或训练器；两视图由调用者提供。当前私有槽**没有**以 G 为条件，尚未接共有独立生存头、anti-collapse、SRO、SCM 或 R4。输出 logits 需要配套明确删失约定的生存损失，不能视为完成训练方法。骨架支持显式 mask 排除填充，不传 mask 时默认所有 token 有效；使用 mask 与原版无 mask 的 loader/预测行为不同，患者公平对照必须显式设计而非直接混用。其 8:0 对照在当前接口尚不支持。

患者输入适配、病理/组学增强有效性、可辨识的任务分解与完整协同估计均尚待完成。目录不会连接任何已有队列，不启动患者训练、推理或服务器任务；保持原仓库已有历史工作及脏文件。
